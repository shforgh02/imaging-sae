# Phase 1b — Stage A sanity checks (exploratory, dev data)

**Plan:** `docs/SANITY_PLAN_v1.md` (approved 2026-11-09) · **Status:** Stage A done 2026-11-09 (A3 SAE rows on Modal L4, the rest local; all sanity rows pass), waiting for the framing decision · **Results:** `RESULTS.md` (generated by `a4_summarize.py` from `results/*.json`)

Post hoc and exploratory, on the 150 dev scans that Phase 1 already used. The Phase 1 verdict (NO-GO), the main code and the main results are
unchanged: these scripts only read `data/p1/` and import the production code. Each script first reproduces an official number (a sanity row).
The reading rules (R-sat, R-fm, R-sae) were written in the plan before any Stage A result. Any claim needs Stage C (frozen protocol, held-out scans).

## Question
Do CT-FM token features and SAEs on them beat simple baselines? There are three parts:
1. Physical features, label-free.
2. The same network, untrained.
3. Clustering or raw channels at matched sparsity and feature count.

The organ-identity probe used in Phase 1 is at ceiling (median AUROC 0.998 for CT-FM and the reference). So the probes also cover harder tasks: boundary tokens, vertebra level, lung lobe, body side, and few labels.

## Scripts
| step | script | runs on | what | output |
|---|---|---|---|---|
| A0 | — | web | novelty check | `NOVELTY.md` |
| A1 | `a1_probe_ladder.py` | CPU | probe ladder: 10 feature sets × tasks T1a, T1b, T2, T3_*, T4 | `results/a1_probe_ladder.json`, `results/a1_cache_full/` |

| A3 | `a3_decomp_fair.py --part cpu` / `--part sae` | CPU / GPU | decompositions at L0 6 and 27, reps 0–2, both chimera rules, 425-feature matched areas, inputs CT-FM / untrained / R3 | `results/a3_cpu.json`, `results/a3_sae.json` |
| A4 | `a4_summarize.py` | CPU | tables and reading rules | `RESULTS.md` |

`common.py` holds the shared code. It covers data loading, the label-free reference ladder (R0–R4), the R3 inputs for perturbed scans, and replicate context. It also has `evaluate()`, which runs the production `p1_fit.feature_table` under both chimera rules (via `c1b_chimera_other.chimera_both`).

Run everything with `powershell -File run_stageA.ps1`. It runs one job at a time and resumes from saved results. Single steps run from this folder with `..\..\.venv\Scripts\python <script>.py`. Every script has a `--quick` smoke mode, whose results go to `*_quick.json` and `RESULTS_quick.md`. Logs are in `logs/`.

## Notes and deviations
- **T3_rib is not estimable.** At 16 mm tokens, ribs almost never reach 50% occupancy of one rib: only rib 1 has ≥ 10 patients. The plan's class rule therefore drops the task. It is recorded as skipped, not re-defined.
- **LR settings.** The probe uses `max_iter = 300`, as in production. Convergence warnings are counted per probe in the A1 log, not hidden.
- **A3 `--part sae` runs on Modal (L4 GPU), not on the local GPU.** The local GPU is power-capped, so this step would take about 3.7 h there.
  - The code is the same: `a3_decomp_fair.load_input` and `fit_eval`.
  - The project has a hard budget of $29 with per-task limits; see `cloud/README.md`.
